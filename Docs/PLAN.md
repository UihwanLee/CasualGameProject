# CasualGameProject 기획서 (v0.2)

> 랜덤 디펜스 장르의 캐주얼 게임 + 자그마한 서버(HTTP + WebSocket) + 데이터 파이프라인 툴
> 목적: 클라이언트 구조, **실시간 서버 연동**, 툴 제작 역량을 하나의 프로젝트로 보여주는 포트폴리오

---

## 1. 게임 컨셉
- 장르: 캐주얼 랜덤 디펜스 (세로 모바일 화면)
- 한 줄 소개: 몬스터가 경로를 따라 돌고, 골드로 유닛을 **랜덤 소환 → 합성**해 웨이브를 버틴다.
- 패배 조건: 필드 위 몬스터 수가 한도(예: 100)를 넘으면 패배
- **핵심 설계 포인트**: 소환 결과(확률)와 재화는 **서버가 결정**하고, 클라이언트는 결과를 받아 연출만 한다.
  치트 방지라는 명분이 있고, 패킷 순서·에러 코드·재접속 복구·연출과 상태의 동기화를 자연스럽게 다룰 수 있다.
- 리소스: Where-Are-You-Looking-At의 에셋 재사용 (Tiny Swords, UI MEGA Pack, Layer Lab, Effect_Vol.1, 사운드)

## 2. 핵심 루프
1. 로그인(HTTP) → 게임 세션 접속(WebSocket)
2. 웨이브 시작 → 몬스터가 경로를 따라 순환
3. 몬스터 처치 → 골드 획득 (클라가 보고, 서버가 검증·적립)
4. 소환 요청 → **서버가 등급 결정** → 클라가 소환 연출
5. 같은 유닛 N개 → 합성 요청 → 서버 확정 → 합성 연출
6. 앱 백그라운드 전환이나 네트워크 끊김 → **재접속 시 서버 스냅샷으로 보드 복구**
7. 게임 종료 → 최고 웨이브 저장, 랭킹 등록

## 3. 기술 목표
| 영역 | 목표 | 증명 방법 |
|---|---|---|
| 실시간 통신 | WebSocket 세션, 시퀀스 번호 기반 요청/응답 매칭, 에러 코드 체계 | 프로토콜 문서 + 패킷 로그 |
| 재접속 | 끊김 감지 → 자동 재접속 → 스냅샷으로 상태 복구 | 비행기 모드 on/off 시연 영상 |
| 상태 관리 | UniTask + 상태 머신으로 연출 중 응답, 실패 응답, 끊김에도 상태가 어긋나지 않음 | 시퀀스 다이어그램 + 테스트 |
| 모바일 생명주기 | OnApplicationPause/Focus, 네트워크 변경 대응 | 실기기 시연 |
| 성능 | 몬스터 300마리 + 유닛 50기에서 모바일 60fps, 전투 중 GC Alloc 0 | Profiler Before/After |
| 리소스 | Addressables로 리소스 로드/해제 | 메모리 프로파일 |
| 툴 | Excel/CSV → JSON + C# 데이터 클래스 자동 생성, 유효성 검사 | 에디터 툴 GIF |
| 공통 | **같은 데이터 테이블을 클라·서버가 공유** | 파이프라인 다이어그램 |
| 품질 | Unity Test Framework + GitHub Actions 빌드/테스트 | CI 배지 |

## 4. 시스템 구성
```
[Excel/CSV 기획 테이블]
        │  (DataTool: 변환 + 검증 + 코드 생성)
        ▼
   JSON 테이블 ──────────────────────┐
        │                             │
        ▼                             ▼
[Unity Client]                  [ASP.NET Core Server]
 - 전투 / 연출 (DOTween)  ─HTTP─▶ - 게스트 로그인 (JWT), 랭킹
 - 네트워크 모듈 (UniTask) ─WS──▶ - 게임 세션: 소환/합성/재화 확정
 - 패킷 로거                      - 세션 스냅샷 (재접속 복구)
 - 상태 머신                      - SQLite (EF Core)
```
프로토콜 상세는 [네트워크 프로토콜 설계](Design/01_네트워크_프로토콜.md)를 참고한다.

## 5. 저장소 구조 (예정)
```
CasualGameProject/
├─ Client/      Unity 6 프로젝트 (6000.3.11f1)
├─ Server/      ASP.NET Core (Web API + WebSocket)
├─ Shared/      패킷 정의, 에러 코드 (클라·서버 공용 C#)
├─ DataTable/   원본 Excel/CSV + 변환된 JSON
└─ Docs/        기획, 설계, 트러블슈팅 문서
```

| M4 | 재접속·상태 복구, 모바일 생명주기, 에러 코드 처리 | 비행기 모드 시연 통과 |
| M5 | 최적화, 테스트, CI, 문서화 | 3장 수치 달성, README 완성 |

## 7. 규칙
- **유료 에셋 보호**: 저장소는 Private 유지. 외부 에셋은 `Client/Assets/ThirdParty/`에 모아두고, 공개할 때는 스크립트만 공개
- **회사 프로젝트(BunkerDefense)의 코드·에셋·기획 문서는 사용하지 않음.** 처음부터 직접 설계
- AI가 작성한 코드는 이해하고 설명할 수 있을 때만 커밋
- 문제 해결 과정은 `Docs/Troubleshooting/`에 바로 기록 (문제 → 원인 → 해결 → 결과)
- 커밋 컨벤션: `feat:`, `fix:`, `chore:`, `docs:`, `refactor:`
