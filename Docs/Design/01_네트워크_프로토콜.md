# 네트워크 프로토콜 설계 (초안 v0.1)

> M3 구현 전에 확정할 초안. 구현하면서 바뀐 내용은 이 문서에 먼저 반영한다.

## 1. 채널 구분
| 채널 | 용도 | 예 |
|---|---|---|
| HTTP (REST) | 상태가 없는 요청 | 게스트 로그인, 랭킹 조회, 테이블 버전 확인 |
| WebSocket | 게임 세션 중 실시간 요청/이벤트 | 소환, 합성, 골드 정산, 스냅샷, 하트비트 |

## 2. 메시지 형식 (JSON, 이후 MessagePack 검토)
```json
// 클라 → 서버 (요청)
{ "type": "SummonReq", "seq": 12, "body": { } }

// 서버 → 클라 (응답) : 요청의 seq를 그대로 돌려줌
{ "type": "SummonRes", "seq": 12, "code": 0, "body": { "unitId": 1003, "slot": 5, "gold": 120 } }

// 서버 → 클라 (푸시 이벤트) : 서버 자체 순번 eventSeq
{ "type": "WaveStartNtf", "eventSeq": 40, "body": { "wave": 7 } }
```
- `seq`: 클라가 요청마다 1씩 증가시킨다. 응답 매칭과 중복 요청 방지에 쓴다.
- `eventSeq`: 서버 푸시 순번. 클라는 마지막으로 처리한 값을 기억하고, 중복이나 역순 이벤트는 버린다.
- `code`: 0이면 성공, 그 외는 에러 코드 표를 따른다.

## 3. 에러 코드 (초안)
| 코드 | 이름 | 클라 처리 |
|---|---|---|
| 0 | Ok | 확정 |
| 1001 | NotEnoughGold | 롤백 + "골드 부족" 토스트 |
| 1002 | BoardFull | 롤백 + "슬롯 부족" 토스트 |
| 1003 | InvalidMerge | 롤백 + 보드를 스냅샷으로 재동기화 |
| 2001 | DuplicateSeq | 무시 (이미 처리된 요청) |
| 3001 | SessionExpired | 재로그인 |
| 9000 | ServerError | 롤백 + 재시도 안내 |

에러 코드 enum은 `Shared/`에 두고 클라와 서버가 같은 파일을 쓴다.

## 4. 요청 처리 흐름 (소환)
```
Client                                   Server
  │ 버튼 클릭 → 상태: Requesting            │
  │──── SummonReq(seq=12) ─────────────────▶│ 골드 검사, 확률 추첨
  │   (대기 연출 시작, 타임아웃 5초)          │
  │◀─── SummonRes(seq=12, code=0) ──────────│
  │ 상태: Animating → 소환 연출 → Confirmed  │
```
- 타임아웃이 나면 재접속 흐름으로 넘어가고, 스냅샷으로 결과를 확인한다. (요청이 서버에서 처리됐을 수도 있기 때문)
- 응답이 오기 전에는 같은 버튼을 다시 누를 수 없다.

## 5. 재접속과 상태 복구
```
끊김 감지 (하트비트 미수신 / 소켓 에러 / OnApplicationPause 복귀)
  → 입력 잠금 + "재연결 중" UI
  → 재접속 (지수 백오프: 1s, 2s, 4s ... 최대 5회)
  → ResumeReq(sessionToken, lastEventSeq)
  → ResumeRes(전체 스냅샷: 골드, 웨이브, 보드, 몬스터 수, 현재 eventSeq)
  → 로컬 상태 교체 → 화면 재구성 → 입력 해제
  → 실패하면 타이틀로 이동
```

## 6. 디버깅
- 클라와 서버 모두 송수신 패킷을 `[시간][방향][type][seq][code]` 형식으로 기록한다.
- 클라 개발 빌드에서는 패킷 로그 뷰어(디버그 UI)를 띄울 수 있게 한다.
- 버그를 재현하면 패킷 로그를 `Docs/Troubleshooting/`에 함께 첨부한다.

## 7. 미정 사항
- [ ] 전투 판정(몬스터 처치)을 클라가 할지 서버가 할지 → 1차: 클라 판정 + 서버는 골드 상한만 검증
- [ ] 직렬화 방식 (JSON → MessagePack 전환 시점)
- [ ] 서버 세션 저장소 (메모리 → 필요하면 SQLite에 스냅샷 저장)
